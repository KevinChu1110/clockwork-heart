## 1. 現狀診斷：AI 生成遊戲的數值與互動通病剖析

在目前的開發實踐中，由 AI 程式碼生成的數值與裝備系統普遍呈現「平淡、無感、缺乏黏著度」的特徵。經過深層逆向工程與體驗診斷，核心病徵可歸結為以下三點：

### 1.1 純加法平直思維 vs. 乘區爆發（Additive vs. Multiplicative）
- **AI 寫法的通病**：裝備屬性通常被設計為單純的線性加法，如 `攻擊力 +5`、`生命值 +30`。從 1 級到 30 級，數值曲線是一條平滑的直線。玩家更換一件裝備，整體傷害僅從 100 變為 104（成長僅 4%），在戰鬥中打怪的刀數完全沒有變化，玩家感知極度遲鈍（數值脫敏）。
- **商業爆款解法**：導入「乘區聯動（Multiplicative Buckets）」與「階梯閾值（Breakpoints）」。一件新裝備不僅提供基礎白字，更能直接開闢新的獨立乘區（例如：發條轉速提升 20% 激活過載力矩 1.5 倍），使換裝體感呈現跳躍式爆發（Power Spike），單次換裝成長達到 20%~40%。

### 1.2 數值木樁（Stat Stick） vs. 機制質變（Gameplay Shift）
- **AI 寫法的通病**：高階裝備與低階裝備的差異僅僅是「數字變大」，缺乏對戰鬥行為、手感與操作節奏的干預。紫裝打起來跟白裝一樣，只是跳出的傷害數字不同，無法形成真正的 Build（流派構建）。
- **商業爆款解法**：高階副詞條必須帶來「行為質變」。例如：原先單體刺擊的發條刀刃，在鑲嵌特定機芯後產生「發條回火：暴擊時噴射金屬齒輪碎片穿透後排」，讓打寶不只是追逐數字，而是「解鎖全新的戰鬥爽感」。

### 1.3 反饋延遲與結算無感 vs. 即時多巴胺微循環
- **AI 寫法的通病**：掉落處理多半是一行靜默的 `player.inventory.append(item)`，結算時在結尾彈窗一行文字。缺少掉落瞬間的視聽衝擊、開箱的懸念鋪墊、換裝瞬間的數值震動反饋。
- **商業爆款解法**：建立極短反應鏈（0.2s 物理掉落光柱 -> 0.5s 金屬齒輪音效撞擊 -> 1s 數值滾動翻騰 -> 30s 驗證碾壓），將心理多巴胺分泌推至頂點。

## 2. 熱門刷寶／放置手遊調研與核心機制拆解

為建立《發條之心》的極致爽感驅動模型，深入剖析市場上五大成功標竿產品：

### 2.1 《劍與遠征》（AFK Arena / AFK Journey）
- **裝備核心架構**：白、綠、藍、紫、金、紅、白金等嚴格品階；搭配「種族加成（Faction Bonus +25%）」與「T1~T4 專屬進階石」。
- **戰力數值驅動**：**戰力壓制（Combat Deficit Penalty）**。當玩家戰力低於關卡推薦戰力時，怪物獲得隱性免傷與高額攻擊補正，造成「差 5% 戰力就被團滅」的卡點；而一旦合成出一件紅裝、戰力越過門檻，原本滅頂的關卡瞬間反轉為「全隊大招橫掃」。
- **心理機制**：**「卡關積累焦慮 -> 換裝瞬間翻盤」**，製造極致的情緒落差（Catharsis）。

### 2.2 《塔塔冒險隊》與休閒開箱類（菇勇者傳說 / 瘋狂騎士團）
- **裝備核心架構**：以「單鍵開箱」為唯一核心，無限替換裝備。裝備品質涵蓋普通、精良、稀有、傳奇、逆天。
- **副詞條設計**：主屬性（攻防血）穩步增長，副詞條直接決定戰鬥流派（暴擊流、連擊流、反擊流、閃避流、擊暈流）。
- **心理機制**：**變動比率增強時程（Variable Ratio Reinforcement Schedule）**。開箱零門檻、戰力即時動態比對（顯著的綠色向上箭頭 + 滾動數字 + 戰力數值大紅字跳動），玩家在 10 分鐘內可觸發數十次多巴胺刺激，成癮性極強。

### 2.3 《楓之谷M》（MapleStory M / TMS）
- **裝備核心架構**：原版 TMS 經典數值反饋——**素質色階系統**與**潛能方塊洗練**。
- **素質色階反饋**：灰(<0)、白(0)、橘(1~4)、藍(5~22)、紫(23~39)、金(40~54)、綠(55~69)、紅(70+)。掉落的每一件裝備在基礎屬性上都具備隨機浮動，讓每一次拾取都是一次「開盲盒」，期待看見金光、綠光甚至紅光的極品素質。
- **洗練與強化拉扯**：方塊洗出 3 排相同屬性（如 3 排物理攻擊力%）引發社群尖叫；星力強化時清脆的鐵錘聲、成功時的星光音效、以及「防爆機制」給予的安全感。

### 2.4 《暗黑破壞神：不朽》（Diablo Immortal）/《火炬之光：無限》
- **裝備核心架構**：前綴（Prefix）與後綴（Suffix）隨機池；主屬性數值區間 Roll 點（Min-Max Range）；傳奇威能（Legendary Affix）改變技能核心機制。
- **打寶儀式感（Drop Ceremony）**：
  - 遠距離擊殺菁英怪時，一道奪目的暗金/橙色光柱破空而起，並伴隨厚重金屬敲擊的特殊音效（Ding!）。
  - 裝備拾取進背包時帶有「問號未鑑定」狀態，點擊鑑定時卷軸展開、金光綻放，揭曉頂級詞條。

### 2.5 《彈殼特攻隊》（Survivor.io） / 《弓箭傳說》（Archero）
- **品質質變階梯**：
  - 綠色／藍色：提供基礎攻擊與生命加成。
  - 紫色（Epic）：**質變觸發**（例如：苦無升紫獲得自瞄連射、太刀升紫獲得劍氣外放）。
  - 金色（Legendary）：數值乘區翻倍、被動頻率縮短。
  - 紅色（Mythic）：神話專屬機制，徹底顛覆清怪效率。
- **心理機制**：玩家在追求合出一件「紫裝」時具有不可動搖的目標感，因為它實質改變了遊戲的遊玩手感。

## 3. 裝備隨機副詞條（Affix）系統架構設計

為使《發條之心》的打寶具有深度與長線追求，結合發條玩具世界的金屬機件設定，建立三層隨機詞條體系：

### 3.1 主屬性浮動區間（Base Stat Float Range）
掉落裝備的主屬性並非固定死板數值，而是依據零件出廠公差進行 **85% ~ 115%** 的偏態隨機分佈：

| :--- | :--- | :--- | :--- | :--- |
| **85% ~ 94%** | 出廠公差偏差 | 灰（降屬） | 15% | 金屬邊角稍有磨損，基礎性能偏低 |
| **95% ~ 105%** | 標準規格標準件 | 白（基礎） | 60% | 標配精密發條板件 |
| **106% ~ 109%** | 精選合金件 | 橘（小浮動） | 15% | 咬合緊密，數值小幅領先 |
| **110% ~ 113%** | 鍛造良品 | 藍（中階） | 7% | 齒輪表面經手工拋光，性能突出 |

### 3.4 機芯精密校準（Reforge & Calibration）機制
徹底貫徹 Kevin 的八色階準則與安全防線：
1. **7 次校準上限（Max 7 Calibrations）**：每件裝備最多進行 7 次調校，防止無限洗練導致數值通膨。
2. **安全彈簧保障（No Break / No Downgrade）**：
   - 嚴格遵守「失敗不碎裝、不降階」原則（`break_on_fail: false`, `delete_on_fail: false`）。
   - 每次校準結果只有四種可能：**維持原狀（40%）、微調上升 +1（30%）、精密躍升 +2（10%）、微幅未契合失調（20%，但不扣除既有色階門檻）**。
3. **第 7 次大師保底（Master Pity Rule）**：若前 6 次均未達到金色以上，第 7 次校準觸發「極限鎖合」，必定跳躍至少 1 階（Min Jump = 1），為玩家提供穩定的付費與努力預期。

## 4. 戰力公式重構與數值跳升（Power Spike）模型

### 4.1 傳統平淡公式的致命缺陷
許多遊戲與預設 AI 採用線性加權戰力公式：
$$\text{平淡戰力} = \text{ATK} \times 2.5 + \text{DEF} \times 2.0 + \text{HP} \times 0.5$$
此公式的致命缺陷在於：**屬性之間彼此孤立，互不影響**。玩家堆疊 100 點攻擊與 500 點生命值，戰力成長是線性疊加的；但實戰中，暴擊率、暴擊傷害與攻擊力是互為相乘的，防禦力與生命值結合構成「有效生命值（Effective HP）」。

### 4.2 改良版非線性戰力公式（Multi-Bucket Combat Power）
我們建立一套反映「實戰真實爆發力」的乘區戰力公式：

$$\mathbf{CP} = \left[ \mathbf{EDP} \times 2.8 + \mathbf{EHP} \times 0.6 \right] \times \mathbf{M}_{\text{quality}} \times \left(1 + \mathbf{R}_{\text{resonance}}\right)$$

其中各核心因子定義如下：

1. **有效輸出潛能（Effective Damage Potential, EDP）**：
   $$\mathbf{EDP} = \text{ATK} \times \left( 1 + \frac{\text{CRIT}\%}{100} \times \frac{\text{CRIT\_DMG}\% - 100}{100} \right) \times \left( 1 + \frac{\text{ARMOR\_PEN}}{200} \right)$$
   - 當玩家同時獲得攻擊力與暴擊率時，戰力呈現**幾何級數放大**，直觀呈現出 Build 成型的暴增感。
2. **有效生存體質（Effective Health Pool, EHP）**：
   $$\mathbf{EHP} = \frac{\text{HP}}{1 - \min\left(0.80, \frac{\text{DEF}}{\text{DEF} + 300}\right)} \times \left( 1 + \frac{\text{DMG\_RED}\%}{100} \right)$$
   - 防禦與免傷不再是死板數字，而是與生命值形成綜合坦度。
3. **品質階級係數（$M_{\text{quality}}$）**：
   - 凡品（1.00） $\rightarrow$ 良品（1.25） $\rightarrow$ 上品（1.60） $\rightarrow$ 秘寶（2.10） $\rightarrow$ 神工（2.80）。
4. **齒輪共振套裝加成（$R_{\text{resonance}}$）**：
   - 激活 2 件套：$+0.08$
   - 激活 3 件套：$+0.18$
   - 激活全套 5 件套：$+0.35$

### 4.3 換裝暴漲（Power Spike）數值實測曲線
對齊現有 `power_progression.json` 的 T1 ~ T5 階梯，換上一件頂級裝備時的戰力反饋對比如下：

```

  2400 |                                                    [★ T5 秘寶神裝: 2,250]
  2000 |                                                ▲ (Power Spike +38%)
  1600 |                                       [T4 秘寶: 1,320]
  1200 |                              ▲ (Power Spike +32%)
```

```gdscript
## 計算裝備或角色的非線性爆發戰力值 (Combat Power)
static func calculate_combat_power(stats: Dictionary, resonance_bonus: float = 0.0) -> int:
	var atk: float = float(stats.get("atk", 10))
	var def: float = float(stats.get("def", 5))
	var hp: float = float(stats.get("hp", 100))
	var crit: float = float(stats.get("crit", 5.0))
	var crit_dmg: float = float(stats.get("crit_dmg", 150.0))
	var pen: float = float(stats.get("armor_pen", 0.0))
	var dmg_red: float = float(stats.get("dmg_red", 0.0))

	# 1. 有效傷害乘區 (Effective Damage Potential)
	var crit_mult: float = 1.0 + (clampf(crit, 0.0, 100.0) / 100.0) * ((crit_dmg - 100.0) / 100.0)
	var pen_mult: float = 1.0 + (pen / 250.0)
	var edp: float = atk * crit_mult * pen_mult

	# 2. 有效生存體質 (Effective Health Pool)
	var def_reduction: float = clampf(def / (def + 300.0), 0.0, 0.80)
	var ehp: float = (hp / maxf(0.20, 1.0 - def_reduction)) * (1.0 + clampf(dmg_red, 0.0, 50.0) / 100.0)

	# 3. 綜合評分與套裝加成
	var base_cp: float = (edp * 2.8) + (ehp * 0.60)
	var final_cp: float = base_cp * (1.0 + resonance_bonus)

	return int(round(final_cp))

## 根據數值分數獲取對應的八色階資訊
static func get_tier_info_from_score(score: int) -> Dictionary:
	for tier in COLOR_TIER_THRESHOLDS:
		if score >= tier["min"] and score <= tier["max"]:
			return tier
	return COLOR_TIER_THRESHOLDS[1] # 預設 white

## 隨機生成一件裝備的副詞條組合
static func roll_equipment_affixes(tier: int, quality: String) -> Array[Dictionary]:
	var affixes: Array[Dictionary] = []
	var slot_count: int = 0
	match quality:
		"common": slot_count = 0
		"uncommon": slot_count = 1
		"rare": slot_count = 2
		"epic": slot_count = 3
		"artifact": slot_count = 4
		_: slot_count = 0

	for i in range(slot_count):
		# 根據品質抽取目標色階權重
		var rolled_score: int = _roll_score_for_quality(quality)
		var tier_data = get_tier_info_from_score(rolled_score)
		affixes.append({
			"slot_index": i,
			"affix_id": "affix_atk_flat" if i % 2 == 0 else "affix_crit_rate",
			"tier_id": tier_data["id"],
			"score": rolled_score,
			"color_hex": tier_data["color"].to_html()
		})
	return affixes

static func _roll_score_for_quality(quality: String) -> int:
	match quality:
		"uncommon": return randi_range(1, 10)
		"rare": return randi_range(5, 25)
		"epic": return randi_range(23, 50)
		"artifact": return randi_range(40, 75)
		_: return 0
```
