## 0. 這份文件解決什麼問題

0.19.0 之前，這個專案的問題不是不好玩，是**產品身份沒有鎖死**：

- 兩套互斥的世界觀並存，玩家看到的內容是舊的，文件寫的是新的
- 已實作或規劃的系統超過 20 個，而核心戰鬥數值模型還沒鎖版
- 文件寫「手機＋電腦雙端」，技術基礎是桌面單機
- 沒有一句話能回答「玩家明天為什麼要再打開這個遊戲」

本文件把這四件事一次鎖死。**鎖死的意思是：要改，得改這份文件，而不是繞過它。**

## 1. 產品身份（鎖定）

### 1.1 一句話

> **一群被遺忘的機械玩具，在一個停止運轉的世界裡重新醒來。**

這是本作唯一的產品核心。角色 IP、視覺辨識、劇情、收藏、短影音、手機遊戲循環，
全部從這一句話長出來。

### 1.2 產品定位句（對外）

> **單機核心 ＋ 輕連線的跨平台 RPG。**
> EN: *A single-player-first cross-platform RPG with light online touches.*

⛔ **不要同時宣稱「純單機遊戲」與「手機長期營運遊戲」**——那會讓玩家、也讓自己混亂。
對外一律用上面這一句。

### 1.3 對標

| 對標對象 | 我們要學的 | 我們不學的 |
|---|---|---|
| 楓之谷 M | 角色養成、裝備、長期成長 | MMO 社交規模、伺服器營運強度 |
| 貓咪大戰爭 | 解鎖 → 強化 → 推圖 → 收集的清晰循環、角色 IP 化 | 極簡玩法深度 |

### 1.4 平台優先序（**這條會推翻很多既有設計**）

> **手機是第一級平台，PC 是放大版。**

不是「PC 畫面是標準，手機只是縮小版」。任何在手機上不成立的設計，
不管在大螢幕上多好看、多好操作，都是錯的。

### 1.5 目標受眾

- 喜歡輕度 JRPG／放置戰鬥、願意讀劇情的手機玩家
- 被角色與世界觀吸引進來、而不是被系統深度吸引進來的人
- 碎片時間 3～5 分鐘玩一段，也願意週末坐下來推一小時劇情

### 1.6 體驗支柱（依優先序，變現不得凌駕其上）

1. **世界與角色** — 玩具世界的溫暖與孤寂；四位角色要能被單獨記住
2. **即時戰鬥演出** — 站位、出手、受擊、技能特效；10 秒無 UI 也看得出誰在砍誰
3. **養成有情感回饋** — 裝備／戰魂／技能綁「誰教你的、為何而戰」
4. **輕連線** — 看見他人，不破壞沉浸，且**永遠不是必要的**

> 本節取代已刪除的 `VISION.md`。舊的《勇者之魂》體驗支柱作廢。

## 2. 世界觀（鎖定）

### 2.1 唯一 Canon

**玩家在遊戲中看到的所有世界觀，只允許存在《發條之心》。**

舊的《勇者之魂》世界（勇者、魔王、翠嶺、傭兵團、戰後二十年）**全面作廢**。
`VISION.md` 已刪除，不保留為歷史文件——它從未上線過，沒有需要對玩家交代的歷史包袱。

### 2.2 劇情轉譯策略（⛔ 不重寫）

**保留 60～70% 的劇情骨架，只換世界觀表皮、角色動機與名詞。**

現在把 C0～C6 全部砍掉重寫，會連鎖進入「劇本 → 地圖 → NPC → 對話 → 任務 → 翻譯 → QA → 重新產圖」，
半年後還在 C1。所以：

| 保留（不動） | 轉譯（要換） |
|---|---|
| 地圖結構 | 人類 → 玩具 |
| 關卡結構 | 傭兵 → 玩具角色／守護者 |
| 戰鬥流程 | 魔王／黑焰 → 停擺世界的異常核心 |
| NPC 數量 | 武器來源、能量來源 |
| 任務流程 | NPC 身份 |
| 劇情節奏 | 主角動機 |
| 分歧結構 | 所有世界名詞 |

第一版劇情**不需要完美**。現在要的是世界觀一致性，不是文學獎。

### 2.3 之後才補的 IP 核心

轉譯完成後才寫這幾條，它們才是這個 IP 真正的內容：

- 誰替這些玩具上發條？
- 為什麼世界停止？
- 「發條之心」到底是什麼？
- 為什麼小白能醒來？

## 3. 核心循環（鎖定）

### 3.1 主循環

```
探索 → 戰鬥 → 掉落 → 養成 → 解鎖玩具／發條 → 新區域 → 劇情
```

**就這一條。** 任何新系統如果不能明確掛在這條循環的某一環上，一律不做。

### 3.2 每日循環（長期鉤子）

> **「今天，誰需要上發條？」**

這是本作的留存設計，也是產品語言本身。

| 項目 | 規格 |
|---|---|
| 觸發 | 玩家每日首次登入，發條之心產生**一個今日異常** |
| 時長 | **3～5 分鐘**完成 |
| 內容 | 一段短內容（一場戰鬥、一次尋物、一次對話選擇） |
| 產出 | 發條碎片 → 幫一位角色／NPC 上發條 |
| 解鎖 | 一則小故事、一段動畫、一個角色表情、或一件收藏品 |

⛔ **不做傳統的「每日任務 1、2、3、4、5」清單。**
每天是**世界發生了一件小事**，不是一張待辦清單。這是這個 IP 的記憶點，不要做成通用手遊皮。

⛔ **不逼肝**：錯過不累積懲罰、不設連續登入斷簽歸零、不做限時焦慮。

### 3.3 養成（簡化為四層，鎖定）

```
角色 → 戰魂 → 裝備 → 技能
```

**四層就夠了。** 戰魂是長線養成鉤子，予以保留，但**大幅簡化**：
⛔ 不做「14 主星 × 大量技能 × 合成 × 入魂 × 多層資源」的完整版。

## 4. 砍掉的東西（鎖定，不得復活）

0.20 起，下列系統**移出範圍**。要復活必須走第 9 節閘門。

| 系統 | 處置 | 理由 | 放棄了什麼 |
|---|---|---|---|
| **公會／週貢獻** | **砍** | 公會＝成員管理、邀請、權限、伺服器資料、社交、排行、反作弊、離線處理、通知……這不是一個功能，是一整套後端產品。而且與「零連線可通關」天然衝突 | 社交 MMO 化 |
| **NG+** | **砍** | 現階段的價值遠低於開發成本。現在要的是「玩家第一次玩完之後想再打開」，不是「把整個遊戲再打一遍」 | 重複遊玩深度，換取第一輪完成度 |
| **裂縫** | **砍／延期** | 很容易長成「額外關卡 → 敵人 → 掉落 → 數值 → 平衡」，最後變成第二套遊戲 | Endgame 大型內容池 |
| **戰魂（完整版）** | **簡化保留** | 是最有價值的長線鉤子，但 14 主星＋合成＋入魂＋多層資源太重 | 養成的組合廣度 |

> 三個都砍掉是有代價的，代價已經寫在上表右欄。**接受代價，不要偷偷做回來。**

## 5. 手機化（鎖定，優先於劇情）

這是目前最大的技術風險：文件說手機＋PC，技術基礎仍明顯偏桌面
（Forward Plus 渲染器、1280×720 設計基準、觸控輸入不統一、Web 包 135 MB）。

**⛔ 不換引擎。** Godot 已投入大量實作，換掉等於重來。用下面五件達成手機化。

### 5.1 必做五件

| # | 項目 | 驗收標準 |
|---|---|---|
| 1 | **Mobile renderer** | 建立 Mobile renderer profile 並確認可正常跑；桌面維持現有 profile |
| 2 | **輸入抽象層** | 全部收斂成 `Move / Attack / Interact / Skill / SwitchWeapon / Confirm / Cancel` 七個語意動作。PC 綁鍵鼠／手把，手機綁觸控／虛擬按鍵。⛔ 程式碼裡不得再直接判斷滑鼠或鍵盤 |
| 3 | **響應式 UI** | Safe Area ＋ Anchors ＋ 可縮放 UI。至少測 16:9、19.5:9、20:9、平板、PC。⛔ 1280×720 不再是設計基準 |
| 4 | **觸控優先戰鬥** | **一個玩家只用右手拇指，能不能完成一場戰鬥？** 不能就還是 PC-first，重做。⛔ 不是「PC 遊戲塞一個虛擬搖桿」 |
| 5 | **低階手機 profile** | 建立 Low / Mid / High 三檔。⛔ 不能只在開發機上測 |

### 5.2 包體與分包

| 項目 | 目標 |
|---|---|
| **首次必要下載** | **50～80 MB** |
| 分包內容 | 劇情包、後續地圖、語音、大型素材 |
| 現況 | Web 目錄 135 MB |

目標不是「整個遊戲永遠 < 50 MB」，是**玩家第一次接觸時不要被下載量嚇跑**。

### 5.3 放棄什麼

放棄「PC 畫面是標準、手機只是縮小版」的思維，以及部分 PC-first 的視覺與操作設計。
這是很大的產品思維改變，寫在這裡是為了以後不要反悔。

## 6. 連線範圍（鎖定）

**保留「零連線可通關」，而且這是產品差異化，不是包袱。**

```
主線敘事  ⊂  單機完整
連線內容  ⊂  可選加厚
連線故障  ⇏  卡劇情
```

| 做 | ⛔ 不做 |
|---|---|
| 雲存檔 | 公會（已砍） |
| 他人殘影 | 同圖強制組隊主線 |
| 留言石 | 拍賣行 |
| 通關蠟燭 | 內建語音 |
| 輕排行 | 必須上線才能玩 |

所有核心內容都不得依賴伺服器。設定裡永遠保留純單機模式。

## 7. 美術（鎖定，細節見 ART_DIRECTION.md）

核心關鍵詞：**Mechanical Toy / Worn / Charming**

- 主角小白是**米白色斑駁金屬**打造的發條玩具兔。⛔ 憲章中的「毛絨」已於 2026-09-07 移除，不得復活
- 四位角色：兔（單手長劍）／獅（騎士長槍）／狐（法杖）／野豬（巨錘）
- **三層辨識系統**：30m 看物種輪廓 → 10m 看武器剪影 → 3m 才看螺絲鏽斑
- 優先序：**輪廓 > 顏色區塊 > 武器 > 發條 > 材質細節**
- ⛔ 是「機械玩具」不是「小型機器人」——要螺絲、接縫、手工感、不完全對稱

完整規格與五組產圖提示詞見 `ART_DIRECTION.md`。

## 8. 商業模式（鎖定，細節見 BUSINESS.md）

**F2P ＋ 內購 ＋ 獎勵型廣告 ＋ 一次性去廣告買斷。** 目標是這款遊戲要能賺錢。

四條護欄不得破壞：

1. **第 1.6 節的體驗支柱優先序不變**，變現不得凌駕其上
2. **免費玩家必須能完整通關主線**，主線不刷也能過
3. **廣告不得打斷戰鬥**——⛔ 無插屏、無彈窗，只有玩家主動點擊的獎勵節點
4. **抽魂必須有保底與上限**，⛔ 不做 pay-to-win

> `BUSINESS.md` 與 `DECISIONS.md` 中引用《勇者之魂》原版循環與 `VISION.md` 的段落，已於 2026-09-07 同步更新為引用本文件。

## 9. 新功能准入閘門（0.20 起強制）

任何新的大型系統動工前，必須在這份文件的 §10 變更紀錄留下一筆，並回答完下列六題。
**六題有任何一題答不出來，就是不做。**

| # | 問題 | 不合格的回答 |
|---|---|---|
| 1 | 它掛在 §3.1 核心循環的哪一環？ | 「都有關」「未來會用到」 |
| 2 | 它服務 §1.6 哪一根體驗支柱？第幾優先？ | 說不出來、或只服務第 4 根 |
| 3 | 玩家在**手機上用單手拇指**能不能操作它？ | 「桌面先做，手機之後再說」 |
| 4 | 它需不需要伺服器才能運作？（需要就違反 §6） | 「先做離線版，之後接線上」 |
| 5 | 它會不會讓首包超過 §5.2 的 50～80 MB？ | 沒算過 |
| 6 | 為了做它，要**放棄**什麼？ | 「不用放棄什麼」——只有好處的提案一律退件 |

**額外硬規則**：核心戰鬥數值模型（`BALANCE.md` 的時間模型）**鎖版之前**，
不准新增任何會影響戰鬥數值的系統。
